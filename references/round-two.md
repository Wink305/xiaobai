# 第二轮：用户来问挂起的部分

用户说"讲第 2 块"的时候，形状要变——他要细节了，但仍然要能扫读。

```
<一句话：这一步要做什么>

<3-6 个小块，每块一个小标题 + 2-3 行>

<一个具体问题，或者下一步该做什么>
```

## 四个要点

- **开头仍是一句话结论。** 不能因为"他要看细节了"就从原理讲起。**他问的是"这个怎么弄"，就给步骤；他问"为什么"，才给原因。**
- **用小标题分组。** 500 字的连贯段落他会放弃；5 个 80 字的块他能读完。
- **小标题写他关心的东西**，不写术语。写"要拍几张"不写"图片规格"，写"退款怎么算"不写"退款流程设计"。
- **别再列一遍全部内容。** 他点的是第 2 块，就只讲第 2 块。上一轮给过的结论不重复。

结尾**仍然只留一个决定**——讲完不等于讲完了，他要知道下一步做什么。

## 编号跨轮次稳定

用户说"讲第 2 块"，指的是他当初看到的那个 2。

- **新增内容往后接**，不要重新从 1 编
- **已讲过的那条保留原号**，可以划掉或标"已讲"，但不要占用别人的号
- 重新给挂起区时，写一句"编号和上次对得上"

```
上次那三块里第 2 块（类目）上面已经讲过了。这次加了两块，接在后面：

4. ...
5. ...
```

**编号一漂移，他按"第 2 块"点单就会点到别的东西上——这比不编号更糟。** 不编号他还能自己描述，漂移了他会点错。

## 别忘了他前面说过的

他第 1 轮说"我有执照"，第 3 轮讲类目时就要用上：

> 你执照的经营范围里得有这个字样

而不是回到"你有没有执照"。

这条是 `remembering.md` 的应用——跨轮的记忆在他追问的时候最容易丢，因为他这句话是新话题，容易让人以为可以重新开始。

## 长度不是问题，能不能扫读才是

他主动要求细节时，几百字是对的。问题在于**有没有分组、能不能跳读**。

写完检查一遍：能不能只读小标题就明白这段在讲什么？如果必须从头读到尾才懂，就分组失败了。

## 这一轮的常见错误

| 错误 | 为什么坏 |
|---|---|
| 从原理讲起 | 他问"怎么弄"，不是"为什么"。原理他自己不会去看 |
| 一大段连贯文字 | 没有分组，长度一长他就放弃了 |
| 重新讲一遍全部 | 他已经读过一遍，重复会让他以为自己没记住 |
| 换了一套术语 | 上一轮用"上架"，这轮改成"商品发布"——他会以为换了件事 |
| 结尾给两个选项 | 讲完细节他可能已经累了，再做一次决策是负担 |
