# 术语 → 白话对照

> **本表为中文。** 用户用其他语言提问时，不要把这里的类比硬翻给他——那些类比依赖中文语境的日常经验（个体户、微信、监管所），翻成英文往往不成立。
>
> 表里没有对应词时，**用他那个语言里能解释清楚的类比**，或者干脆直说这个词的含义。前一条规则"不要临场编类比"的意思是"别跳过查阅"，不是"没有就不许说"。

**用之前先想一件事**：这个词在用户的世界里是什么意思？如果用户是开店的，"服务器"是词；如果用户是要签合同的，"违约责任"才是词。别把技术词硬套到不懂技术的用户身上。

## 证照与资质（漏一条就会白跑或被拦）

这一类属于 A 类硬信息（缺了用户迈不出那一步），**不属于可挂起内容**。涉及开店、接单、收款、发布时先查这一节。

| 术语 | 白话说法 |
|---|---|
| 营业执照 | 开门做生意的凭证，写着店名和法人，线下店和网店都要 |
| 个体工商户 | 一个人开的小店，不用开公司，出了事个人担 |
| 食品经营许可证 | 卖吃的要有的证，管厨房干不干净，蛋糕属于食品 |
| 卫生许可证 | 早年卖食品用的证，现在多数地方已并入食品经营许可证 |
| 行业许可 / 资质 | 特定行业才能做的证明，比如开诊所、教培、卖成品油 |
| ICP 备案 | 网站上线前要办的登记，国内服务器上的网站都要 |
| 平台准入 | 平台愿意让你开店卖东西的前置条件，各家不一样 |
| 资质核验 | 平台检查你证件真不真、符不符合它的类目要求 |
| 类目 | 平台把卖的东西分类，蛋糕属于哪一类决定了要哪些证 |
| 无证经营 | 没该办的证就开张，卖吃的是违法的，可能被处罚停业 |
| 三证齐全 | 执照 + 你本人的身份证 + 对应的行业许可证都齐了 |

## 打包、签名与许可证

这一节面向"要把东西交到别人手上"的场景。只自己用的话可以先不管。

| 术语 | 白话说法 |
|---|---|
| 打包 | 把一堆源码变成一个双击就能开的文件。这一步新手通常要失败几次，不是你笨 |
| exe | Windows 上能双击运行的程序文件 |
| 源码 | 程序员写的那些看得懂的指令 |
| 签名（数字签名） | 给这个文件盖一个"这是谁做的"的章。Windows 认章，不认就拦 |
| 数字证书 | 签名的那个章。要花钱买 |
| SmartScreen | Windows 的自带提醒，没签名的程序会被它拦下。**这不是病毒** |
| "更多信息→仍要运行" | 绕过 SmartScreen 的正常操作，第一次用要先知道 |
| 杀软误报 | 没签名的程序被杀毒软件当成病毒。**很常见，不是真的病毒** |
| 许可证（LICENSE） | 这个项目的"授权书"，写着你能不能用、能不能改、要不要公开 |
| 开源 | 公开了源码，**不等于随便用**。有些只准内部用，有些必须公开你的改动 |
| "没有 LICENSE" | 默认保留所有权利，**等于不能用** |
| API 密钥 | 让 AI 干活的钥匙，也是你的身份。**泄露等于别人花你的钱** |
| 按量计费 | 用一次扣一次钱，不是买断。**agent 读文件来回试，比普通聊天费得多** |
| 本地跑 vs 云端跑 | 本地不花钱但折腾、吃硬件；云端开箱即用但每次扣钱 |
| 自动更新 | 程序自己升级。**自己做的 exe 不会自动更新**，用户得重新下载 |
| 分发 | 把程序给别人。渠道、下载、打不开的问题都在这一步 |

## 登录、认证与隐私

vibe coding 的人最常在这里卡住，而且这几个是**最黏的选择**——学员/客户习惯之后基本改不了。用户判断不了技术，只能判断"用户习不习惯""改起来麻不麻烦"。

| 术语 | 白话说法 |
|---|---|
| 登录 | 怎么证明"这个人是他声称的那个人" |
| 认证（auth） | 验证身份这一步 |
| 授权 | 验证完了，准不准你拿他的数据 |
| 一键登录 / 第三方登录 | 用微信、Google 登录，不用自己设密码。用户点一下就进来了 |
| 账号密码 | 自己注册、自己设密码。少了"点一下就进来"的方便，但和微信生态脱节 |
| 验证码 | 发一条短信或邮件让你输一串数字，证明手机号是你的 |
| OpenID | 微信给你的一串用户编号，认出"这是同一个人"，不含个人信息 |
| Session / Token | 登录之后的"通行证"，证明你现在还是刚才那个人 |
| 会话过期 | 通行证失效了，要重新登录 |
| 双因素认证 | 光有密码不够，还要第二步（短信、App、硬件码） |
| 权限 | 谁能看什么。管理员能看到所有人的，教练只能看自己的课 |
| 角色 | 一组权限的打包：管理员 / 教练 / 学员 |
| 越权 | 本来只能看自己的，却能看到别人的数据——严重问题 |
| 个人信息 | 能认出"这个人是谁"的数据：姓名、手机号、身份证号、住址、照片、位置 |
| 敏感个人信息 | 出事后果特别重的那类：身份证号、生物识别（指纹、人脸）、健康信息、行踪、账户 |
| 告知与同意 | 用之前得告诉用户收集了什么、他能不能拒绝，不能默默收 |
| 数据备份 | 留一份副本，数据坏了能恢复 |
| 数据迁移 | 把数据搬到另一个系统/服务商。**很多平台不提供导出，搬走就等于重做** |

> **这一类最黏。** 登录方式、用户习惯、已经积累的数据，一旦定下来别人就习惯了，改的代价极高。给这类选择时必须明说"这个以后改起来麻烦，而且用户会不适应"——别让它看起来像和选数据库一样轻。

## 部署与运维

| 术语 | 白话说法 |
|---|---|
| 部署 | 把新版本放到线上的服务器上，让用户能打开 |
| 上线 | 部署完成，真实用户已经能访问 |
| 灰度 | 先只让一小部分用户看到新版本，确认没问题再全放 |
| 回滚 | 把线上退回上一个能用的版本 |
| 环境（开发/测试/生产） | 三个隔离的地址：开发是你改的，测试是同事验收的，生产是真实用户用的 |
| 服务器 | 一直开着的电脑，负责把网页发给用户 |
| 数据库 | 存数据的地方，网站记下的东西都在这儿 |
| 备份 | 给数据留一份原件，出事能拿回来 |
| 监控 | 自动盯着服务是否还活着，坏了就报警 |

## 开发与代码

| 术语 | 白话说法 |
|---|---|
| 前端 | 用户看到、能点的那部分 |
| 后端 | 用户看不到、负责处理数据和逻辑的那部分 |
| 接口（API） | 后端开的一个窗口，前端按约定往里递东西、从里面拿东西 |
| bug | 程序算错了或表现跟预期不一样 |
| 重构 | 不改变外部表现，把内部代码理顺，让它更好维护 |
| 代码审查 | 别人在你合并之前看一遍，拦下问题 |
| 单元测试 | 给一小块代码单独做的自检 |
| 版本控制 | 每次改动都存一个可回退的快照 |
| 依赖 | 你的项目要用的别人写好的现成零件 |
| 缓存 | 把算过的结果先存着，下次直接拿，不再重算 |
| 并发 | 多人同时发起请求时程序不崩的处理方式 |
| 异步 | 任务在后台跑，先去干别的，好了再回来 |

## 数据与 AI

| 术语 | 白话说法 |
|---|---|
| 数据集 | 一堆用来喂给模型看的例子 |
| 训练 | 让模型从大量例子里学规律 |
| 推理 | 训练完之后，实际拿模型算一个答案 |
| 微调 | 在现成模型上再补一点特定场景的例子的训练 |
| 幻觉 | 模型一本正经地编造不存在的事实 |
| 幻觉率 | 编造内容出现的频率 |
| 提示词（prompt） | 你给模型的指令原文 |
| 上下文窗口 | 模型一次能"看见"的文字上限，超了就得砍 |
| RAG | 先从资料库里找出相关片段，再让模型照着片段回答，减少瞎编 |
| 微调 vs RAG | 微调是重新教它；RAG 是让它开卷考试时能翻书 |
| 幻觉抑制 | 加规则或查证，减少模型编造 |
| 评测集 | 一批事先准备好的题目，用来测模型改动到底是好是坏 |
| 量化 | 把模型参数压小，让它跑得更快更省内存，代价是可能略微变笨 |

## 商业与产品

| 术语 | 白话说法 |
|---|---|
| MVP | 能验证这件事值不值得做的最小版本，功能少但能跑通 |
| PMF | 真的有用户愿意持续用、愿意付钱 |
| A/B 测试 | 两版页面各给一半人看，看哪版效果好 |
| 转化率 | 进来的人里有多少完成了你要他做的那件事 |
| 留存 | 用过之后还回来用的比例 |
| 灰度用户 | 提前试用新功能的那部分用户 |
| 埋点 | 在程序里埋下记录，统计用户在哪点了什么 |
| DAU / MAU | 每天 / 每月来用的人 |
| ROI | 花一块钱换回多少 |
| 留存曲线 | 用得越久还剩多少人 |
| S曲线 | 新事物普及先慢、后快、再慢的曲线 |
| 第二增长曲线 | 现有主业之外找到的新增长点 |

| 术语 | 白话说法 |
|---|---|
| 排期 | 排在什么时候做 |
| 里程碑 | 一个可以验收的阶段成果 |

## 合同与法务

不懂技术的用户常在这栽跟头——不是看不懂字，是不知道哪几条在保护他。

| 术语 | 白话说法 |
|---|---|
| 主体资格 | 跟你签的这家公司是不是真的存在、还在正常经营 |
| 授权代表 | 签字的那个人有没有权利替公司签这份合同 |
| 生效条件 | 什么情况下这份合同才算成立，比如签字+盖章+付定金 |
| 付款节奏 | 什么时候给钱：全款预付 / 尾款 / 分期，各自风险不一样 |
| 违约责任 | 对方说话不算数时你能拿到什么，通常写得比"赔偿损失"具体 |
| 不可抗力 | 哪些情况谁都不算错，比如天灾、疫情、突发政策 |
| 争议解决 | 出问题去哪告：仲裁还是法院，这决定你能不能在本地维权 |
| 排他条款 | 签了就不能再跟同行合作，这类最容易漏看 |
| 知识产权归属 | 做出来的东西归谁所有 |
| 竞业限制 | 离职后一段时间内不能做同行，范围和期限要看清 |
| 保密条款 | 签了之后哪些事你不能往外说 |
| 阴阳条款 | 正面写着一条，附件或小字里写着相反的 |
| 格式条款 | 合同里由一方事先写死的条款，通常对弱势方不利 |
| 霸王条款 | 明显不平等、对方无权修改的条款 |
| 违约金 | 约定好的赔偿金额，可以高于实际损失 |
| 定金 | 有担保性质，违约不退；和"订金"（可退）差一个字，性质完全不同 |
| 订金 | 预付的钱，一般可以退 |
| 诉讼时效 | 出了事必须在几年内告，过了就失去权利 |

## 财税

| 术语 | 白话说法 |
|---|---|
| 发票 | 买东西拿到的凭证，公司没它不能算成本 |
| 增值税 | 商品和服务产生的税，买东西你出、卖东西别人出 |
| 所得税 | 赚的钱要交的一类税 |
| 核定征收 | 税按固定额度交，不用请会计记账 |
| 查账征收 | 账目清楚按实际利润算税，要记账 |
| 个体户免税额度 | 小规模纳税人有免税起征点，有上限，不是永远免税 |
| 小规模纳税人 | 年销售额小、税率低但通常不能开专票 |
| 一般纳税人 | 规模大、税率高但能开增值税专用发票 |
| 社保 | 强制交的保障，交了才能用医保、领退休金，不是可选项 |
| 公积金 | 单位必须一起交的住房储蓄 |
| 成本票 | 能证明你花了多少钱的凭证，没它不能抵税 |
| 账期 | 对方欠你货款多久，大公司常压几个月，小公司要现结 |
| 现金流 | 手里实际有多少钱周转，能接单但没现金照样会倒闭 |

## 医疗与健康

这类场景里，安全优先于可读性——**不确定就说不确定，不要给医疗判断**。

| 术语 | 白话说法 |
|---|---|
| 执业医师证 | 医生行医的资格，没证不能独立看诊 |
| 执业许可 | 机构被允许开展诊疗的批件 |
| 适应症 | 什么情况下这个治疗是适用并被批准的 |
| 禁忌症 | 什么情况下绝对不能做，风险高到医生要劝退 |
| 知情同意 | 医生必须把风险讲清楚、你签字确认 |
| 术前评估 | 手术前查你的身体能不能扛住 |
| 恢复期 | 多久能正常工作、多久要复查 |
| 并发症 | 治疗过程中可能出现的意外，不是医疗事故 |
| 适应人群 | 哪类人适合做，哪类人不适合 |
| 二期临床 | 新药在更多真人身上试，尚未正式获批 |
| 医保报销 | 哪些费用国家出、哪些自己出，比例各地不同 |

> **这一节的红线**：涉及用药剂量、诊断结论、要不要手术，一律不给判断。改成"这个得问医生"，并告诉用户该问医生哪几个问题。这不是保守，是把话说准。
