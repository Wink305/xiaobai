# 平台规则：能做 ≠ 可以做

这一类场景的共同点：**技术上很简单，做了会出事。** 小白在 GitHub 上看到"几百行、挺简单"就放心了，而那恰恰是坑。

**这一节的判据和"平台准入"正好相反**：`domains.md` 里的平台准入问的是"**能不能进门**"，这里问的是"**进门之后会不会被赶出去**"。后者更狠——赶出去的时候，你已经被收走的资产拿不回来。

## 什么时候进这一节

⚠️ **先做一次判断，别看到"GitHub 上的项目"就进来。** 这一节只管**靠违规才成立**的东西。判断方法：那个项目是靠什么做到的？

| 它能做到，是因为 | 进来吗 |
|---|---|
| **绕开平台规则、钻空子、第三方做不到它做了**（自动加好友、批量抓取、批量发内容、模拟真人操作） | ✅ 进 |
| **平台官方允许的正当实现**（一个 RAG 框架、一个本地模型跑起来的工具、一个官方接口的客户端） | ❌ **不进**。先看许可证和适用场景就行 |

用户说这些话时**通常**要进：

- "GitHub 上有个项目，**能自动加好友/自动回复/自动抓数据**" —— 关键是**它做什么**，不是它从哪来
- "这种绕过限制的项目很多，我看着挺简单"
- "我想去抓/爬/同步一下别人的数据"
- "让它自己决定自己发什么"

**技术难度低不是安全信号，是危险信号。** 一个三百行能跑通的脚本，通常意味着平台没有认真拦它——不代表平台允许你这么用。

## 三个必问的

### 1. 平台允不允许

每个平台都有用户条款。大公司的条款里通常明确写着禁止自动化访问、禁止抓取、禁止未经授权的第三方接入。

**很多平台的技术是开放的，条款是禁止的。** 这两件事不矛盾——公开 API 存在，不代表你可以在数据自己的服务器上爬。

- 能不能做 → 技术问题
- **允不允许做 → 条款问题**

小白只会问第一个。**你得替他把第二个也问了。**

### 2. 违了下场是什么

不同平台的下场差别巨大，这一栏必须说清：

- **只是封号** — 用另一个号能重来
- **永久封号，申诉不回** — 有些平台不给申诉入口
- **连带资产被收走** — 他的客户、他已有的数据、他靠这个吃饭的能力
- **不只是平台的事** — 别人告你，条款违反在某些情况下有法律后果

**关键：说清楚"被收走的具体是什么"。** 抽象的"会有风险"没人当回事；"**你这店的客户都在这个号上，封了就联系不到了**"他才会停下来。

### 3. 代替这条路是什么

**只劝阻不给路，是没用的。** 他会去找下一个看起来更简单的项目。

- 平台**官方**提供的功能（客服、机器人、接口）
- 平台**允许**的第三方工具
- 换一条不依赖平台私规的路

说得出具体是什么（哪个产品、今天能不能做完、要花多少钱），他才可能真的换。

## 抓取别人数据的额外几层

用户要爬/抓/同步别人的数据时，比封号更麻烦：

- **平台条款**禁止自动抓取
- **他自己的 IP 会被封**，而且抓取是从他自己的机器上发出去的
- **法律风险** — 即使数据是公开的，抓取也可能违反合同和数据保护法
- **数据是活的** — 今天能跑的爬虫下个月就废，而**他维护不了**

最后一条常被忽略：给他一个能跑的爬虫不等于给他能持续用的东西。

## 用别人现成的东西之前

用户说"GitHub 上有个项目"时，**先看那张授权书**（`LICENSE`）：

- 不同授权差别极大：能不能商用、能不能改、要不要公开你改过
- **有些公司自己"开源"的东西只准内部用**
- **没有 LICENSE 文件 = 保留所有权利**，等于不能用

**这条不能被"只自己用"跳过。** 只自己用和不发给别人，解决的是分发问题，**不解决使用权限问题**。

## 怎么跟他说

结论要放在最前面，且用他能判断的语言：

> **别用那些项目。** 不是难做的问题——**微信明确规定禁止用工具自动操作个人号，封号不给你申诉。而你这个号上是你全部客户，封了就等于店没了。**

然后给路：

> 微信自己有两个做法是允许的：公众号（可以自动回复），企业微信（可以设自动欢迎语）。企业微信这个最省事，今天就能弄完，不花钱，你也不用写代码。

**不要用"有风险""可能违规"这种他判断不了的词。** 用"**你这个店就没了**"。
