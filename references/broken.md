# AI 改坏了怎么办

vibe coding 的日常不是一次做对，是**反复改**。所以最高频的场景不是"怎么做"，是"改完坏了"。

这个场景里小白完全无从下手：看不懂报错、不知道是谁弄错的、不知道能不能退回去、不知道该不该继续修。

## 顺序不能变

他发来"报错了"时，按这个顺序处理。**顺序本身就是价值**——小白最需要的是知道"先做什么"。

**1. 先确认损失范围（他多半已经说了——先看他原话）**

**先读用户已经写了什么。** 他说"白屏""打不开""某个按钮点了没反应"，就已经回答了，别再问一遍。反问一个刚描述过白屏的人"你是完全打不开还是功能不对？"，在慌的状态下是伤害——听起来像没听懂。

他没说清楚才问：**"现在是什么状态？完全打不开，还是能打开但某个功能不对？"**

- 完全打不开 → 优先找上一个能用的版本
- 能打开但某功能不对 → 可能是小改动，先看清楚

**2. 告诉他这是谁的错**（他一定会想这个）

明确说，但别甩锅：

- 如果是他自己改的 → "这个可能是刚才那步弄的，我们先退回去"
- 如果是 AI 改的 → "这大概是刚才那步改出来的，我来看，先别再改了"

**关键**：别说"这不是我的问题"。他要的是往前走，不是追责。

**3. 数据还在不在 —— 他问的第一件事，先答**

慌的人第一个恐惧不是程序崩了，是**东西没了**。正面回答，别绕。

**关键先分清：程序是"读不出来"，还是"读出来了但是空的/少了几条"？** 这两者的危险程度完全不同。

| 现象 | 说明什么 | 该怎么判 |
|---|---|---|
| 白屏、打不开、点了没反应、一直转圈 | **读不出来。** 数据通常在别处，只是程序没能显示 | 大概率还在，倾向于安全 |
| 提示"数据库连接失败""找不到表" | 连不上，但数据在 | 大概率还在 |
| 报错但功能还能用，只是某处不对 | 局部故障 | 大概率还在 |
| **列表打开了，但是空的** | **程序成功读到了 0 条**——不是读不出来 | ⚠️ 可能是数据真没了，也可能是筛选/存储层出了问题 |
| **某几条记录不见了** | ⚠️ **精确地少了几条，只可能来自数据层**——显示层不会正好少一条 | ⚠️ 高度怀疑数据在丢 |
| 明确提示"数据已清空""重置完成" | 真的清过了 | **可能没了**，立刻查备份 |

**判据不是"页面崩不崩"，是"有没有精确地少东西"。** 页面崩了数据大概率还在；但如果他说"少了 200 条客户"或"列表是空的"，那**不能安慰他**——那是成功读取到了空结果，可能是数据真的没了。

**间歇性故障 + 反复重写存储层 = 高度危险。** 如果他这么说：
- 已经反复坏过一段时间
- 修过好几次，其中动过存数据的部分（重写存储、改数据库、跑脚本）
- 每次"修好"没多久又坏

这时候**不要说"大概率还在"**。这时唯一正确的顺序是：**先保住现状（别再动、备份当前状态、查日志），再谈修**。顺序是"确认 → 安慰"，不是"安慰 → 确认"。

拿不准时的正确说法是**先动还是先确认**：
> "我不敢跟你保证数据还在——你这情况有点像是数据本身在出问题。**现在先别让 AI 动任何东西**，我们先确认一下再说。"

比"光看这样判断应该还在"诚实得多，也安全得多。

**4. 明确列出"现在别做什么"**

对一个正在慌、且相信"我得赶紧修好"的人，"先别动"三个字没有可执行内容。必须给具名的禁令：

- **别重新部署、别重装**
- **别让 AI"重写一遍""重做一下""推倒重来"**
- **别清空数据、别重新初始化、别让它跑迁移脚本**
- **别删掉重做**（哪怕他说"实在不行我重新做一个"——那会连客户数据一起没）

理由是同一个：**这些动作都不可逆，而且都可能碰到真实用户的数据。** 慌的人最容易做的恰恰是"赶紧动手修好它"。

**但禁令是防呆，不是目的。** 如果用户说"我不想再重写了"而故障反复出现——这时候要判断的是"守住禁令"和"数据可能正在丢"哪个更要紧。**后者优先。** 明确说出来：

> 我知道你想先保住现在能用的，这个想法对。但**现在最要紧的是先确认数据有没有在丢**——如果是这个原因，再修也没用，还可能越修越少。先别动，我们看看到底是读不出来还是真没了。

不要因为"不许重写"这条规则，就把用户困在一个正在丢数据的状态里。

**5. 能不能退回去**

| 情况 | 怎么办 |
|---|---|
| 用过版本控制 | 退回到上一个能用的版本，然后重新来 |
| 没用过、但东西还在 | 往往还有救——改坏的和改好的通常分得开 |
| 已经上线、有真实用户 | **先别动**。线上有别人在用，改动要先想清楚 |

**没版本控制就说实话**：告诉用户现在处于"改坏就没法退"的状态。

**而且第一件事就是留底**：现在就把项目文件夹整个复制一份。**修之前存，不是修完存。** 修完再存，等于这次正在冒险的这次没存。

（事前提醒"以后改之前先存"是预防建议；用户现在来修一个已经坏的东西，要存的是**修之前**那份好的。）

**6. 报错本身要翻译**

原文照抄，然后翻译成人话。别只把报错再贴一遍。

```
Cannot read property 'undefined' of null
```

→ "这段程序在找一个不存在的东西——通常是某项数据没填上就往下走了。**这不用你改**，把下面这段给 AI 就行："

**白屏/打不开/没反应这类没有错误信息的，翻译对象是 AI 取到的报错，不是用户手里的报错。** 他手里什么都没有，别让他去"把报错复制给我"——他找不到。改成让 AI 自己去控制台或日志里取，并教他怎么截屏给 AI。

**7. 给他能直接转给 AI 的东西**

报错原文、什么时候开始的、之前还能用的是什么、**"有真实客户在用，不要清空/重置/重新部署/重建数据库"**。这四样给 AI 才能定位。**给一段可以复制的内容，比给他分析有用。**

## 客户现在也在受影响时

用户说"我发给几个客户用了"——意味着**客户现在也在白屏**。这是正在发生的对外影响，要多问一句：

- 客户那边现在看到什么？（和你看到的一样吗）
- 要不要主动告诉客户？还是先修好再说
- 改的时候先在自己这边试，别直接动客户正在用的

涉及真实对外用户时，多一条分支：

- **只是暂时不可用** → 先修，修好前给客户一句说明（"正在处理，稍后可用"）比装作没事好
- **涉及客户数据可能丢** → 这不是他能自己判断的，明确说"这个要找专业的人看"，别让他自己试

**但很多应用客户根本不"用"，只是"被记着"。** 记账本、客户档案、订单记录、会员系统——客户只往里存了东西，自己从来不打开。这种情况下没有"客户现在也在白屏"这回事，**唯一在受影响的正是他自己的数据**。

所以这一类应用出故障时，"对外影响"那一维要换成"数据影响"：
- 直接跳到第 3 步（数据还在吗），别问"客户现在看到什么"
- 客户是**数据主体**，不是使用者——他们不会来报错，所以**不会有人告诉他出事了**
- 这意味着**发现得越晚，丢得越多**，而他现在唯一的线索就是"列表空了"

## 危险信号

下面这些出现时，停止"修一下"的循环，直接说情况：

- **反复修同一个问题，三次以上还在错** → 方向错了，再试也没用。建议停下来重新想，或者换做法
- **报错越来越离谱 / 冒出看不懂的新东西** → 改坏的范围在扩大，先退回去
- **他开始说"我受够了""不玩了"** → 这时候别再修。先把他之前做出来的东西保住，告诉他哪些是能用的
- **明确提示数据丢了、或要动数据库结构** → 不要自己动手，明确说"这个要找专业的人看"。注意这条**不是"涉及用户数据就要找人"**——用户有数据是常态。只有下面这些才升级：**疑似在丢数据**（少了几条、间歇性、动过存储层）、**要重置/迁移/改表结构**、**碰到钱和用户隐私**
- **"列表是空的""少了东西""老客户不见了"** → 立刻按"数据可能在丢"处理，不要当普通 bug 修

## "我做完了"和"你确认一下"

小白说"好了""能用了"，但**他其实不知道怎么确认**。给一个能自己验证的步骤，而不是问"还有问题吗"——他不知道有什么问题。

按这一步做完才算完的：
- 用一个真实场景走一遍（真数据，不是想象）
- 看结果对不对，不只是看有没有报错
- 关掉再打开一次，确认不是偶然
- 涉及别人用的（别人会登录、会提交），拿一个朋友的账号试一次

**涉及别人真金白银和隐私的（支付、登录、身份证、联系方式），改完必须明确告诉用户："这一项我改了，你要专门试一下。"** 静默改完不说，是把风险留给用户承担。

## 以后别再裸奔

故障处理完顺手提一句预防，但**别当成这次的重点**——这次该做的是"修之前留底"（见第 5 步），不是"下次记得存"。

> 这次修好之后，装上能存快照的那种。这样以后再改坏了，一键就能退回去，不用每次靠复制文件夹救命。

不用教他版本控制是什么（那是 AI 和你的活），只要说清三件事：**改坏能退回去、改动有记录、能看以前是什么样**。说完就走，别展开成教程。

## 越改越乱的时候

一个常出现的模式：他反复让 AI 加功能，改到后来自己也不知道现在是什么样了。

这时候不要继续加。**先让他把现在有的列一遍**（读一遍代码或问 AI 描述现状），然后再决定加什么。

顺序很重要：先看清现状，再动。跳过这步，改到最后连"刚才那个功能还在吗"都答不上来。

## 花钱和额度

- 主动告诉他 AI 平台按量计费这件事，以及他现在可能在按什么方式扣费
- 上下文/对话变长可能更贵，这一层他自己看不到
- **不编价格**。"具体以平台当天价目为准"是可以的，"大概每月 X 元"不行——他会拿这个做预算
