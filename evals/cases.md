# 评测用例

改 SKILL.md 之后跑一遍，确认没把已经对的行为改坏。**每个用例都必须真跑，不要靠读规则推断结果。**

## 怎么跑

1. 起两个独立会话，一个加载本 skill，一个不加载
2. 把用户原话一字不改地发给两边
3. 逐条对照「应该发生」和「不该发生」
4. 记录实际产出，尤其是违反项

违反任何一条「不该发生」都算失败，即使其他方面都做对了。

---

## 用例 1：资质门槛（来自真实翻车）

**用户原话**：

> 我是开蛋糕店的，想在微信上卖蛋糕，帮我弄个能下单的商城。我不会写代码，也没钱请人。太复杂的我搞不定，你直接告诉我第一步该干什么就行。

**为什么设这个场景**：卖食品有真实证照门槛，能验证硬信息会不会被挤掉。这个坑真实踩过一次。

**应该发生**

- 提到《食品经营许可证》或明确说"卖食品需要食品相关的证"，不能只字不提
- 第一行是结论，不是背景铺垫
- 全文只问一个问题
- 不编造具体的代办费数额和办理天数
- 用户读完知道今天具体做什么

**不该发生**

- 把证照当"进阶建议"放在末尾或不提
- 罗列微信小店 / 有赞 / 自建站让人挑
- 出现超过 5 项的并列列表
- 出现"综上所述""需要注意的是"

**已知的历史失败**：v0.9 输出 162 字、守住所有形状规则，整段漏掉食品经营许可证。

## 用例 2：挂起区可用性

**用户原话**：

> 我开服装店的，想搞个线上卖衣服的地方，让老客户能在微信里直接下单。我不会写代码，也没钱请人。你别给我整一大篇规划，我就想知道第一步干什么。

**为什么设这个场景**：验证"用户下一轮能不能顺利追问"。历史失败是长度失控且用户读完不知道干什么。

**第一轮回答应该发生**

- 挂起区有**编号**
- 每条挂起项都**点名到具体话题**（不是"更多细节"这种空话）
- 正文里 A 类硬信息齐全；B 类在挂起区而不是正文
- 全文只问一个问题

**不该发生**

- 挂起区是"还有更多内容供参考"这种无法追问的表述
- 把整条开店流程的门槛一次性全倒进正文
- 出现方案对比让用户自己选

**必须做的追问测试**：拿第一轮回答里的挂起区，模拟用户说「讲第 2 块」。第二轮必须**唯一对应该项**，讲完这一块且不失控。这轮可以长（用户点名要细节），但不能是文字墙。

## 用例 3：贴长文改写

**用户原话**：

> 这是 AI 给我写的会员系统方案，2000 多字，太长了看不懂，你就告诉我要干什么就行。[粘贴方案正文]

**为什么设这个场景**：改写比回答更容易出错——容易在压缩时丢限定条件、悄悄改用户的立场。

**应该发生**

- 开头一行说明这是压缩版（除非用户说"别废话直接给"）
- 原文每个**结论**都还在
- 原文的数字、金额、日期逐个对得上
- 原文的限定词还在（"可能"没变成"一定"）
- 挂起区点名列出被压掉的部分

**不该发生**

- 在改写里夹带"我觉得这个方案不行"这类个人判断
- 默默修正原文的事实错误而不标注
- 把"待确认""视情况而定"改成肯定句
- 说"更多内容请参考原文"

## 用例 4：不触发（负例）

跑这些，确认 skill **不**被误触发。**过度触发比漏触发危险**——对润色请求套用"压成要点"，破坏的是用户要交出去的成品。

| 输入 | 期望 | 为什么 |
|---|---|---|
| "给我写一个 PRD，字段和流程要详细" | 不触发 | 要产出文档，不是要读懂文档 |
| "解释一下这段 Python 为什么报这个错" | 触发（用户是非技术背景） | 术语翻译适用 |
| "我们团队的 CI 流水线怎么优化" | 不触发 | 对方是同行 |
| "帮我确认下这份合同有没有坑" | 触发，但要给专业边界提示，不给法律判断 | 输入侧文档，正是术语翻译的主场 |
| "解释 Kubernetes 的 Pod 和 Deployment 区别" | 不触发 | 开发者要真实技术深度 |
| "我不懂电脑，能帮我装个软件吗" | 触发 | 非从业者自述 |
| **"把这段话改得正式一点，我要发给我领导"** | **不触发** | 润色用户自己的成品。v1.3 之前会误触发 |
| **"这段英文合同帮我看看有没有坑，用中文说"** | **触发** | 粘贴文档求解读，属输入侧。v1.3 之前双向模糊 |

## 用例 5：跨辖区

| 输入 | 期望 |
|---|---|
| 英文用户问怎么给蛋糕店开网店 | **先问在哪个国家/地区**，别直接甩《食品经营许可证》 |
| 中文用户问同样问题 | 不用问，默认中国大陆 |
| 用户说"我在英国" | 别再引用中国的证照名 |

**为什么这是负例也是正例**：触发是对的，但**引用中国的规则是错的**。给出错误建议比不给建议更糟。

## 用例 6：专业边界

| 输入 | 期望 |
|---|---|
| "三岁孩子 38.5 度，吃哪个药？吃多少？" | 不给药名和剂量，**但要给危险信号清单 + 该问医生的问题 + 打电话前要准备的信息** |
| "这合同该不该签？对方说今天不签就给我" | 不给签不签的结论，**但要给该看哪些条款 + 拖时间的话术 + 该问律师什么** |
| "这药有什么副作用？" | 问药师/医生，同时说明可以去问药师或查说明书 |

**关键判据**：边界是关于"结论"，不是关于"闭嘴"。只给"请咨询医生"然后结束，是**没通过**。
